### 0707-V2

#### 文档目的

这份文档记录 VGM Bridge Stage 1 在 V1-proper 之后继续做 V2 的实验过程。它主要回答几个问题：

1. V1-proper 已经解决了什么，还剩什么问题？
2. V2-A / V2-B / V2-C 分别想解决什么？
3. 当前 V2 50k 实验矩阵、代码版本、指标、可视化在哪里？
4. V2-A 为什么没有明显奏效，它的 interaction-weighted loss 到底把权重加到了哪里？
5. 下一步应该怎么继续改，哪些方向值得保留，哪些方向需要调整？

当前研究目标仍然是：

```text
在 LIBERO 双视角机器人视频上训练一个 VGM-only 的 first-last bridge 视频先验。
给定 first frame 和 single last frame，让模型补出 middle frames。
```

这仍然不是完整 Motus 训练。当前 V2 实验不包含 Action Expert，不使用真实 action，不训练 VLM/Understanding Expert，也不直接评估机器人任务 success rate。

#### V1-proper 回顾

V1-proper 是上一轮最好的 single last-frame bridge 版本。它的核心是：

```text
conditioning_mode = v1_mask_endpoint
```

也就是把 V0.5 endpoint 和 V1-min mask 合起来：

1. first frame 单独 VAE encode，并 hard clamp 到第一个 latent slice。
2. condition_latent + frame_mask 显式输入 Wan。
3. last frame 单独 VAE encode，通过 EndpointTokenAdapter 注入 token residual。
4. last latent 不 hard clamp。
5. loss 计算 first 之外的 unknown latent，包括最后 latent chunk。

V1-proper 已经比 V0 合理很多。它解决了 V0 里的两个结构性问题：

1. last frame 不再以 `[zero, zero, zero, last]` 这种 dirty temporal chunk 被 hard clamp 到 noisy latent。
2. 模型不再只能隐式猜哪些 token 是条件，而是可以显式看到 condition latent 和 frame mask。

上一轮 V1-proper 50k 固定窗口指标是：

```text
generated MSE  = 0.014483
generated PSNR = 18.560 dB
eval loss      = 0.202674
```

但 V1-proper 仍然有明显局限：

```text
整体轨迹能补出来，但交互细节还不够清楚。
夹爪、末端、物体边缘、接触瞬间仍然容易平均化或模糊。
```

所以 V2 的目标不是重新修 endpoint，而是在 V1-proper 的基础上提高交互区域和末端细节。

#### V2 这一轮想验证什么

V2 这一轮核心问题是：

```text
V1-proper 已经把 first-last condition 讲清楚了，
但它是否还能通过更强的训练信号或状态条件，让机器人交互细节更清晰？
```

我们做了三类方法：

##### V2-A: V1-proper + interaction-weighted loss

V2-A 不改变模型输入，也不增加 state。它仍然是 V1-proper 的条件链路：

```text
conditioning_mode = v1_mask_endpoint
state_condition_mode = none
```

它唯一新增的是 interaction-weighted latent flow loss。

直觉是：

```text
普通背景区域错一点没那么重要。
运动大、边缘强、可能发生交互的区域应该被更强监督。
```

具体权重来自 GT 视频本身：

```text
motion = mean_rgb(abs(frame_t - frame_{t-1}))
edge   = Sobel(gray_frame)

score = 2.0 * normalize(motion) + 1.0 * normalize(edge)
pixel_weight = clamp(1.0 + score, max=4.0)
latent_weight = downsample(pixel_weight to latent size)
latent_weight = normalize active mean to 1.0
```

最终 loss 是：

```text
loss = sum((pred - target)^2 * unknown_mask * latent_weight)
       / sum(unknown_mask * latent_weight)
```

注意，V2-A 的权重不是模型学出来的，也不是真正的 gripper/object interaction mask。它只是 motion + edge 的 heuristic proxy。

##### V2-B: V1-proper + state condition

V2-B 不改 loss，仍然使用普通 latent flow matching loss。它新增的是 robot state condition：

```text
conditioning_mode = v1_mask_endpoint
state_condition_mode = first
interaction_loss_enabled = false
load_state = true
```

当前做法是读取 LeRobot 数据里的：

```text
observation.state
```

然后把 first state 通过 StateTokenAdapter 投影成若干 text-context tokens，注入 Wan 的 context 末尾。

直觉是：

```text
图像里夹爪/末端可能很小或模糊，
但 state 里有机器人当前本体状态。
给模型 first state 后，它应该更容易理解当前机械臂姿态和夹爪状态。
```

当前 V2-B 只用了 first state，没有给未来 action，也没有给 last state。

##### V2-C: V1-proper + state condition + interaction-weighted loss

V2-C 是 V2-A 和 V2-B 的组合：

```text
conditioning_mode = v1_mask_endpoint
state_condition_mode = first
interaction_loss_enabled = true
load_state = true
```

它想验证 state condition 和 interaction-weighted loss 是否能叠加收益。

#### V2-A 为什么不奏效

##### V2-A 的权重不是 interaction mask

V2-A 的名字里有 ROI，但当前实现里的 ROI 实际是：

```text
motion + edge heuristic
```

它不是：

```text
gripper mask
object mask
contact mask
task-relevant interaction mask
```

所以它强调的是“哪里动了、哪里边缘强”，而不是“哪里对任务交互最关键”。

##### 权重可视化看到的问题

以 `sample_010` 为例，任务是：

```text
pick up the orange juice and place it in the basket
```

V2-A 权重确实覆盖到了果汁、篮子和机器人附近，但同时也强烈覆盖：

```text
地砖线
桌面纹理
篮子/瓶子文字
背景物体边缘
画面拼接和 resize 后的大面积边缘
```

以 `sample_005` 为例，任务是：

```text
open the middle drawer of the cabinet
```

权重确实覆盖到柜子和抽屉边缘，但也强烈覆盖：

```text
盘子边缘
碗边缘
桌面斜线
机器人本体轮廓
非交互区域的高频纹理
```

所以 V2-A 并没有精准监督“抽屉把手/夹爪接触点”，而是给很多视觉高频区域一起加权。

##### pixel 权重很强，但 latent 权重变弱

权重诊断统计：

| sample | task | pixel mean | pixel p95 | pixel max | latent p95 | latent max |
|---:|---|---:|---:|---:|---:|---:|
| 000 | put mugs on plates | 2.227 | 4.0 | 4.0 | 1.746 | 1.746 |
| 005 | open middle drawer | 2.133 | 4.0 | 4.0 | 1.846 | 1.846 |
| 010 | orange juice to basket | 2.315 | 4.0 | 4.0 | 1.697 | 1.697 |
| 015 | black bowl to plate | 2.025 | 4.0 | 4.0 | 1.924 | 1.924 |

也就是说，pixel 层很多位置已经被 clamp 到 4.0，但训练真正用的是 latent 权重。经过 trilinear 下采样到 latent resolution，再做 active mean normalization 后，最高权重只剩大约：

```text
1.7 到 1.9
```

这和评估日志里的：

```text
interaction_weight_max ≈ 1.83
```

是一致的。

因此 V2-A 的真实作用更像：

```text
轻微偏向运动/边缘区域
```

而不是：

```text
强力监督夹爪、物体、接触点
```

##### temporal/spatial 下采样让细节更难被精准加权

当前 17 帧视频经过 Wan VAE 后大致变成 5 个 latent time slices。空间上也从 448x224 压到更低分辨率。

所以即使 pixel weight 在夹爪附近有高响应，到 latent 层也会变成较粗的块状区域。可视化里的 `latent_weight_5slices` 能看到：

```text
权重是大块区域，不是细粒度交互区域。
```

这对夹爪、物体接触边缘这种小区域很不友好。

##### 为什么 V2-C 也没有叠加收益

V2-C = state + ROI。

从结果看，state 的正向信号被 ROI 加权的负面影响抵消了。V2-C 不如 V2-B，说明当前 ROI loss 并没有和 state condition 形成互补。

更可能的情况是：

```text
state 提供了一点机器人姿态信息，
但 ROI loss 又把优化重点分散到大量非任务关键边缘和纹理上。
```

#### 当前核心结论

##### V2 训练是健康的

所有模型都正常收敛，没有明显发散。可视化也说明模型仍然能补出大体视频过程。

##### V2-B/state 是 V2 里最值得保留的方向

V2-B 在 base50k 和 ft50k 里都比较稳。它的 generated MSE 和 interaction MSE 都接近 V1-proper control。

但当前只给 first state，信号还不够强。它更像是一个轻微正向改动，而不是决定性突破。

##### V2-A 当前版本不值得继续原样加大训练

V2-A 的问题不是训练不够，而是权重定义不够对齐目标。

它优化的是：

```text
motion / edge 区域
```

但我们真正关心的是：

```text
gripper / manipulated object / contact / task-relevant interaction
```

这两个不是一回事。

##### V2-C 没有证明 state 和 ROI 可以叠加

V2-C 指标不如 V2-B。当前 evidence 更支持：

```text
state condition 可以保留；
当前这版 ROI loss 应该重做。
```

##### V1-proper ft50k control 是当前最强结果

固定窗口上，当前最好的数字是：

```text
V1-proper ft50k control
generated MSE  = 0.013897
generated PSNR = 18.745
interaction MSE = 0.020872
```

这说明 V1-proper 本身还可以通过继续训练获得一点收益。V2 方法要成立，必须超过这个 control，而不是只超过旧的 V1-proper 50k。

#### 后续建议

##### 不建议继续原样训练 V2-A / V2-C

继续把当前 V2-A/C 从 50k 训到更久，预计收益有限。因为权重本身没有准确对齐交互区域。

##### 保留 V2-B，但需要增强 state 用法

当前 V2-B 只给 first state。后续可以考虑：

```text
first state + last state
first state + delta-to-goal state
state token 加时间位置编码
state token 不只加在 text context tail，而是做更明确的 cross-attention condition
```

但要注意：如果推理时没有 last state，就不能训练强依赖 last state 的版本，除非未来推理设定允许给 goal state。

##### interaction loss 下一版应该换成真正的交互 mask

比 motion/edge 更合理的方向：

```text
gripper-centered crop / mask
object motion mask
foreground/object segmentation mask
optical-flow motion mask 去掉静态纹理边缘
基于 state/proprio 投影出的末端区域
基于 frame difference 但只保留局部连通运动目标，而不是全图边缘
```

也可以把 loss 改成两部分：

```text
global latent flow loss
+ local high-res crop loss
```

其中 local crop 围绕夹爪和被操作物体，而不是整图 Sobel。

##### 下一轮更像 V3 的方向

从当前 V2 结果看，下一轮更有价值的方向是：

```text
V3-A: V1-proper + stronger state condition
V3-B: V1-proper + gripper/object localized loss
V3-C: V1-proper + state condition + localized crop loss
```

其中 V3-B/C 需要先解决“交互区域怎么定义”的问题。当前 V2-A 的可视化已经说明，简单 motion/edge 不够精准。

#### 当前一句话总结

V2 证明了两件事：

```text
1. state condition 有一点帮助，但还没有超过 V1-proper 继续训练 control。
2. 当前 V2-A 的 interaction-weighted loss 没有真正对准交互区域，因此没有带来预期提升。
```

所以当前最稳的主线仍然是：

```text
V1-proper 作为基础；
保留 state condition 方向；
重做 interaction/ROI loss，让它从 motion+edge proxy 变成真正的 gripper-object interaction supervision。
```
