### 0706V1

#### 文档目的

这份文档记录 `VGM Bridge Stage 1` 从 V0 走到 V0.5 / V1 的实验过程。它主要回答四个问题：

```text
1. V0 版本发现了什么问题？
2. 我们参考了什么已有做法？
3. V0.5 / V1 具体改了什么，训练流程是什么？
4. 当前实验结果、指标、可视化和代码版本在哪里，后续如何追溯？
```

当前研究目标仍然是：

```text
在 LIBERO 双视角机器人视频上训练一个 VGM-only 的 first-last bridge 视频先验。
给定起点帧和终点帧，让模型补出中间过程。
后续再考虑把这个视频过程先验接到 progress / value / reward / action 相关模块上。
```

这不是完整 Motus 训练。当前实验不包含 Action Expert、proprio/state 条件、真实 action 条件、VLM/Understanding Expert，也不直接评估机器人任务 success rate。

#### 核心结论

1. V0 能跑通 first-last bridge，但它的首尾条件方式有结构性问题，尤其容易在尾部出现灰雾、半透明块和最后几帧质量下降。
2. Tail4 旧实验验证了灰雾问题和 VAE temporal chunk 边界强相关。给模型最后 4 个真实 sampled frames 后，尾部质量明显改善，但任务也变成了“给定真实 tail 补中间”，不再是严格 single last-frame bridge。
3. V0.5 / V1 的目标是继续保持 single last-frame bridge，同时修复 V0 的条件注入方式。
4. 当前 50k step 结果里，`V1-proper mask+endpoint` 是 V0.5 / V1 三组中指标最好的版本。它在 16 个固定窗口上的 generated MSE 为 `0.014483`，generated PSNR 为 `18.560 dB`。
5. 和旧 V0 相比，V1-proper 的 generated MSE 从 `0.028123` 降到 `0.014483`，约下降 `48.5%`。和旧 Tail4 相比，generated MSE 也从 `0.017495` 降到 `0.014483`，约下降 `17.2%`。
6. 这说明 V1-proper 确实缓解了 V0 的 endpoint conditioning 问题。但它仍然只是 VGM-only 视频先验，不等于完整机器人策略模型。

#### V0 回顾

##### V0 训练流程

V0 的核心流程是：

```text
1. full_video = [first, middle..., last]
2. clean_full_latent = VAE(full_video)

3. condition_video = [first, zeros..., last]
4. condition_latent = VAE(condition_video)

5. 对 clean_full_latent 加噪，得到 noisy_video_latent

6. known_mask = first latent slice + last latent slice
7. noisy_video_latent[known] = condition_latent[known]

8. Wan 输入 noisy_video_latent
9. loss 只算 unknown middle latent
```

所以 V0 里 Wan 真正看到的是：

```text
x = [clean first latent, noisy middle latent..., clean/condition last latent]
```

##### V0 的问题

V0 的问题不只是“没训练够”，而是条件注入方式有两个结构性缺陷。

第一，last frame 是通过 `condition_video = [first, zeros..., last]` 整段 VAE encode 得到的。17 帧实验里，VAE temporal latent 大致对应：

```text
z0 <- frame 0
z1 <- frames 1-4
z2 <- frames 5-8
z3 <- frames 9-12
z4 <- frames 13-16
```

如果只有最后一帧是真实的，那么最后一个 latent chunk 实际上更接近：

```text
z4 <- [zero, zero, zero, last]
```

这个 `z4` 不是干净的 last-frame latent，却被 V0 硬 clamp 到 noisy latent 里。于是模型尾部看到的是一个结构上不干净的条件 chunk，最后几帧容易出现灰雾、半透明块和边界模糊。

第二，V0 没有显式告诉 Wan 哪些 token 是条件，哪些 token 是待生成区域。`condition_latent` 只作为 `x` 的一部分出现，known mask 没有作为显式 condition 输入给 Wan。模型只能从 `timestep=0` 和 token 内容里间接猜条件区域，这是一种 implicit conditioning。

##### Tail4 旧实验说明了什么

Tail4 旧实验给的是：

```text
first frame + last 4 sampled frames
```

它把最后一个 temporal latent chunk 用真实尾部帧填满，因此可以显著缓解 V0 的尾部灰雾。旧实验指标也支持这一点：

| old run | generated MSE | generated PSNR | eval loss |
| --- | ---: | ---: | ---: |
| V0 | 0.028123 | 15.627 | 0.251870 |
| V0 + Lang | 0.029630 | 15.424 | 0.243618 |
| Tail4 | 0.017495 | 17.837 | 0.235519 |
| Tail4 + Lang | 0.018114 | 17.713 | 0.225950 |
| I2V | 0.019831 | 17.256 | 0.223176 |
| I2V + Lang | 0.019356 | 17.328 | 0.219441 |

但 Tail4 的代价是任务定义变了。它解决的是最后 latent chunk 的边界问题，不再严格回答“只给一张 last frame 能不能补中间”。

#### 参考依据

##### Motus / Wan TI2V 的 first-frame 处理

Motus 标准视频训练和 Wan TI2V 的一个关键点是：first frame 通常会被单独 VAE encode，然后通过 teacher forcing / clamp 稳住起始 latent。

这和 V0 里把 `[first, zeros..., last]` 整体 encode 成 condition latent 不完全一样。对于 first frame，单帧独立 encode 更干净，避免把零帧上下文混进条件 latent。

当前 V0.5 / V1 继续沿用这个原则：

```text
first_frame -> VAE([first]) -> first_latent
first_latent hard clamp 到 z0
```

##### Wan I2V 的 mask-guided condition input

Wan I2V 的思想更接近显式条件输入：

```text
model_input = noisy_latent + condition_latent + frame_mask
```

也就是说，模型不只是从 noisy latent 里“猜”哪些位置是条件，而是额外看到：

```text
condition_latent: 条件视频 latent
frame_mask: 哪些 frame 是条件
```

这启发了当前 `V1-min mask`。

##### Sci-Fi / EF-VI 的 endpoint 单独注入

Sci-Fi / EF-VI 这类 endpoint-conditioned video interpolation 的关键思想是：不要把 end frame 当成一段脏 temporal chunk 直接 clamp，而是把 endpoint frame 单独编码，再作为条件注入到生成网络里。

当前实现没有完整复刻 EF-Net。我们只借鉴了高层思想：

```text
last_frame -> 单独 VAE encode -> endpoint adapter -> token residual
```

这样 last frame 不再必须通过 `[zero, zero, zero, last]` 这种脏 chunk 进入主 latent。

#### V0.5 / V1 方案

##### V0.5 endpoint

配置：

```text
configs/vgm_bridge_v0_5_lang.yaml
conditioning_mode: v0_5_endpoint
tail_condition_frames: 1
```

核心变化：

```text
1. first frame 单独 VAE encode
2. first latent hard clamp 到 z0
3. last frame 单独 VAE encode
4. last latent 通过 EndpointTokenAdapter 注入 Wan token
5. last latent slice 不再 hard clamp
6. last latent slice 参与 loss
```

它修的是 V0 最核心的脏尾部 clamp 问题。它还不是完整 mask-guided input，模型仍然主要通过 endpoint token residual 感知终点。

##### V1-min mask

配置：

```text
configs/vgm_bridge_v1_min_lang.yaml
conditioning_mode: v1_mask
mask_channels: 4
tail_condition_frames: 1
```

核心变化：

```text
1. clean_full_latent = VAE([first, middle..., last])
2. condition_video = [first, zeros..., last]
3. condition_latent = VAE(condition_video)
4. first latent 用 VAE([first]) 的单帧 latent 覆盖
5. noisy_video_latent 只 hard clamp first latent
6. model_input = concat(noisy_video_latent, condition_latent, frame_mask)
7. loss 计算 first 之外的 latent，包括最后 latent chunk
```

代码上，Wan patch embedding 从 base latent channel 扩展到：

```text
48 noisy channels + 48 condition channels + 4 mask channels = 100 input channels
```

新增通道 zero-init，因此刚初始化时不会破坏原 Wan patch embedding 的主干行为。

注意，V1-min 仍然有一个不彻底的地方：它的 `condition_latent` 里 last frame 仍然来自 `[first, zeros..., last]` 的整体 VAE encode。区别是它不再把这个脏 last chunk hard clamp 到主 noisy latent 里，而是作为显式 condition 分支给模型参考。

##### V1-proper mask+endpoint

配置：

```text
configs/vgm_bridge_v1_proper_lang.yaml
conditioning_mode: v1_mask_endpoint
mask_channels: 4
tail_condition_frames: 1
```

这是当前最强的 first-last bridge 版本。它把 V1-min 和 V0.5 合起来：

```text
1. first latent 单帧 encode，并 hard clamp
2. condition_latent + frame_mask 显式输入 Wan
3. last frame 单帧 encode，经 EndpointTokenAdapter 注入 token residual
4. last latent 不 hard clamp
5. middle 和 last latent 都参与训练 loss
```

预期收益是：

```text
mask condition 负责告诉模型：哪里是条件，哪里要生成
endpoint adapter 负责提供干净的 last-frame endpoint 语义
主 noisy latent 不再被 dirty last chunk 污染
```

##### 指标解释

`loss.total_loss` 是固定窗口上重新采样 timestep 得到的 latent flow-matching loss。

`generated_mse / generated_psnr` 只看真正生成区域。当前 `tail_condition_frames=1`，所以 generated region 排除了 first frame 和最后一帧：

```text
generated frames = frame 1 ... frame 15
condition frames = frame 0 + frame 16
```

注意：V1 里 last frame 不再 hard clamp，但它仍然是概念上的 endpoint condition。因此 eval 里把 last frame 放进 condition metrics，不放进 generated metrics。判断中间视频质量时，优先看 generated MSE / PSNR 和固定窗口可视化。

##### 可视化观察

从 sample 000 这组看，V1-proper 相比 V0.5 和 V1-min 更稳定：

```text
1. 尾部灰雾和透明块更少
2. 底部视角里的盘子、杯子边界更连贯
3. 后半段画面整体没有 V0.5 那么明显的漂移和局部脏块
4. V1-min 已经比 V0.5 更像显式条件生成，但尾部局部形状仍然会糊
```

这和指标方向一致：

```text
V0.5 generated MSE: 0.016168
V1-min generated MSE: 0.015083
V1-proper generated MSE: 0.014483
```

不过，这还不能说明模型已经学会机器人任务成功执行。它说明的是：

```text
V1-proper 是更干净、更稳定的 VGM first-last bridge 视频先验。
```

它还不是：

```text
可以直接用于机器人闭环控制的完整策略。
```

#### 当前判断

##### V1-proper 是否比 V0 好

是的。从当前固定窗口评估看，V1-proper 明显比 V0 好。

依据有三类：

```text
1. generated MSE 明显下降
2. generated PSNR 明显上升
3. 固定 case 可视化里尾部灰雾和透明块减少
```

旧 V0 的主要失败模式是 endpoint conditioning 结构不对，继续单纯加训练步数不太可能根治。V1-proper 改的是这个结构，所以它比 V0 更接近我们想要的 first-last bridge。

##### V1-proper 是否已经是最终方案

还不是。

当前 V1-proper 仍然是 VGM-only。机器人视频未来本身存在多模态性，尤其是夹爪、接触、物体边缘这些高频细节，单靠 first frame、last frame 和 language，不一定能唯一确定中间轨迹。

如果后续目标是让它更接近 RoboTwin 官方 Motus 的效果，下一步需要考虑：

```text
1. 引入 proprio/state 条件
2. 引入 action 或 latent action 约束
3. 训练 progress / value / reward 相关 head
4. 从 VGM-only 走向更接近完整 Motus 的 joint training
```

##### 推荐后续路线

短期建议：

```text
1. 把 V1-proper 作为新的 Stage 1 主线
2. 用更多固定 windows 做可视化复核，尤其看尾部和夹爪
3. 保留 V0.5 / V1-min 作为 ablation，不再把旧 V0 作为主路线
```

中期建议：

```text
1. 在 V1-proper VGM 基础上加入 proprio/state 条件
2. 做 progress-conditioned 或 action-conditioned 的二阶段训练
3. 评估时不要只看 pixel/latent loss，要加入固定 case 视频、人眼检查和下游 reward/progress 对齐指标
```

#### 一句话总结

V0 证明了 LIBERO first-last VGM bridge 能跑通，但也暴露了 dirty last latent clamp 和 implicit conditioning 的结构问题。V0.5 / V1 借鉴 Wan 的 mask-guided condition、Motus/TI2V 的 first-frame 单独编码，以及 Sci-Fi/EF-VI 风格的 endpoint 单独注入，最终得到 V1-proper。当前 50k step 结果显示 V1-proper 在固定窗口指标和可视化上都优于 V0/V0.5/V1-min，是下一阶段最值得继续推进的 VGM Stage 1 基线。
